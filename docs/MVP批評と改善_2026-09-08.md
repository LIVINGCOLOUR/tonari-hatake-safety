# MVPの３役批評と改善（2026-09-08）

コードと画面操作を対象にした仮想の立場によるレビューです。実際の利用者へのヒアリング結果ではありません。散布者・周辺農家・地域管理者の視点を用い、一部のレビュー実行が利用制限で中断した箇所は主担当が引き継ぎました。

| 批評する立場 | 厳しく見る点 | 今回の改善 |
| --- | --- | --- |
| 忙しい散布者 | 翌日の予定を複製しただけで、前日の実測・確認・中止まで残るのは危険 | 複製は畑・資材・機材等の設定だけ。実績・連絡・確認・同期版は引き継がない |
| 忙しい散布者 | 延期したのに古い日付や確認済みが残り、誰へ連絡し直すか分からない | 延期・中止・再開・予定内容変更ごとに連絡履歴を分離。日程変更時は予報・実測・チェックをリセット。再開は入力した日程で行う |
| 忙しい散布者 | 保存できていないのに次へ進む、画面更新で入力が消える | 主要フォーム保存を失敗時に戻し、入力とエラー表示を残す。同じ予定・立場の画面更新でフォーム下書きを復元 |
| 通知を受ける周辺農家 | 返信を強要されるように見える。「確認」が散布の同意と解釈される | 確認・返信は任意、散布の承諾ではないと明記。未返信の警告を中立な確認記録表示へ変更 |
| 通知を受ける周辺農家 | 古い予定への確認が変更後も有効になっている | 最新内容の確認と過去の確認を分離。中止・延期のお知らせにも確認操作を用意 |
| 通知を受ける周辺農家 | 登録すれば必ず散布者へ伝わるという説明が実装と一致しない | 自動通知しないこと、クラウドの非公開畑の近接共有が準備中であることを明記。公開範囲変更は畑の編集へ案内 |
| 地域管理者 | 未連絡・気象・報告の件数を足して同じ予定を何件にも数えている | 対象日に確認が必要な予定の件数は重複排除。内訳との違いを明確化 |
| 地域管理者 | 対象ゼロを連絡完了と扱い、把握できていない畑まで安全に見せる | 畑未選択は未完了。登録対象なしと周辺確認の必要性を表示 |
| 地域管理者 | 地図エラーでアプリ全体を操作できなくなる | 地図生成の失敗を局所化し、予定・畑の一覧操作を継続できる案内を表示 |

## MVPの範囲

通常の散布者画面は「予定・記録」「畑」「設定」の３入口、案件内は予定登録→近隣連絡→当日確認→実施記録の４段階。複数の立場を兼ねる利用者は立場切り替えを使う。ログ・可変散布・サンプル操作などは通常の主導線から外し、詳細デモに限定する。

連絡文のコピーは送信ではない。実際に連絡した方法・日時を記録し、相手の画面上の確認とは分ける。返答だけで散布者の連絡済み記録は作らない。

## 検証

- Nodeテスト199件成功：複製、変更履歴、日程変更後の気象リセット、管理者の重複排除、クラウド用連絡版・日時保存など。
- ブラウザー：通常画面のデスクトップ・モバイル、３役導線、登録済みの立場切り替えと所属制限を確認。
- 案件操作：新規登録→延期→再開→気象→実施記録→再表示、保存失敗時の入力保持、他案件の不変性を確認。
- 追加の回帰確認：延期後の旧確認リセットと履歴保持、フォーム下書きの画面更新後の保持、地図生成失敗時の代替表示。

## 紹介前・本番前に区別すること

今回の成果はレビュー用MVPの改善であり、本番公開・外部送信は行っていない。クラウドの非公開畑の近接共有は未実装で、実際の複数アカウント間の連絡・権限・同期競合は本番相当環境での通し検証が必要。端末サンプルでの検証を実利用者間の到達保証とは扱わない。

「問い合わせゼロ」は保証できない。創立者の方には操作を説明せず、①予定を作る、②延期して連絡し直す、③別の立場へ切り替える、を試してもらい、迷った箇所を観察する。追加機能より先にその迷いを直す。
