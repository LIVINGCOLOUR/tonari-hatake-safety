# ３役・兼務の仮想操作レビュー

確認日：2026-09-09。以下は改善前の観察記録。指摘を受けてアプリ本体を修正し、同日のPC/スマートフォン12組で回帰確認を追加した。現在の機能は [FEATURE_MAP.md](../FEATURE_MAP.md) を参照。招待の実アカウント間検証・本番公開は未実施。

## 結論

切り替えボタンは動くが、兼務者の登録・作業対象・所有圃場・プロフィール変更が一貫していない。最優先は、プロフィール保存による予定の意図しない変更、初回の役割登録で行き止まる問題、位置未登録なのに畑が地図へ出る問題。

既存の通常操作テストが通ることと、初回利用や兼務の操作が分かりやすいことは別だった。修正後は誤更新・下書き・兼務の選択予定・初回空地域・未登録位置・境界採用をブラウザ検証で確認する。

## 確認方法

- PC：1440×900、スマートフォン相当：390×900。
- 散布者のみ、周辺農家のみ、地域管理のみ、散布者＋地域管理、全３役の兼務、所属なしからの初回地域作成。各画面幅で実行、計12組。
- 隔離したChromeコンテキストで実際のHTML・JavaScriptのボタン、入力、表示処理を操作。認証・地域所属・保存先は仮想化し、Supabaseへの通信を遮断。実アカウント・地域・共有データは変更していない。
- 主担当が各立場を想定した操作検証。実際の農家や管理者に対するユーザーテストではない。
- 再実行：`node tools/audit-role-ux.mjs`。既定の確認先は `http://127.0.0.1:4177`、Chrome CDPは9239。
- 記録：`/tmp/hatake-role-audit/findings.json`、同ディレクトリの画面画像。結果は「不具合を観察した記録」であり、正常系テストの合格報告ではない。
- 実環境のRLS、メール・LINEの到達、複数の実利用者間の同期は今回の確認範囲外。

## 各立場の評価

| 仮想利用者 | やりたいこと | 操作して困った点 |
| --- | --- | --- |
| 忙しい散布者 | 予定を追加して近隣へ連絡する | 予定フォームに31個の表示中の名前付き入力要素。文面を手直しした後に返答を記録すると、手直しが消えた |
| 自分の畑を守りたい周辺農家 | 畑の位置と配慮事項を登録し、必要時だけ返信する | 畑の追加で場所を指定していないのに地図に図形が出る。別の予定に返信すると、書きかけの相談文が消えた |
| 地域管理者 | 参加者を招待し、地域の予定を把握する | 招待コードを入力する場所はあるが、発行や既存参加者への役割追加の画面がない |
| 散布者兼地域管理者 | 自分の仕事と地域全体の確認を行き来する | 管理画面で見た予定が散布者画面にも残る。プロフィール保存で立場が戻り、その予定の散布者名まで変わる |
| 散布もする周辺農家（全３役） | 同じ畑で散布を行い、隣の畑の散布も把握する | 所有する散布用圃場が周辺農家側の自分の畑から除外される |

## 指摘と改善案

### 1. プロフィール保存が、既存の予定を変更する【最優先・両画面幅で再現】

散布者をプロフィールの利用区分として登録した兼務者で、地域管理へ切り替え、別の予定を閲覧。設定画面で氏名だけ変更して保存した。

結果は、操作中の立場が地域管理から散布者に戻り、閲覧していた予定 `plan-drone-2` の散布者名も「匿名散布者B」から入力した新しい氏名へ変更された。連絡内容の版は0のまま、事前に入れた周辺農家の確認日時も残った。

原因：[saveProfileFromForm](../js/main.js) がプロフィールの単一のroleを操作中のroleへ戻し、`applyProfileToActivePlan` が表示中の予定へ氏名・連絡先などを反映している。

改善案：プロフィールの保存は本人情報と新規予定の既定値だけを更新する。既存予定への反映は対象を明示した別操作とし、連絡内容を変えた場合は内容変更として扱う。

完了条件：管理画面から氏名を保存しても操作中の立場・既存予定・既存の実施記録が変わらない。本番の他人の記録を更新できたという意味ではなく、今回確認したのはローカル状態の誤変更。

### 2. 初めて地域を作ると、散布者や兼務を登録できない経路がある【最優先・両画面幅で再現】

ログイン済み、プロフィール未登録、地域所属なしの状態で地域を作成した。

作成は成功するが、利用できる立場は地域管理のみ。プロフィールの散布者・周辺農家ボタンが無効になった。既存所属のない人が散布者として始める操作がここで止まる。

原因：`create_workspace_with_admin` は管理の所属を作り、`createSupabaseWorkspace` は選択済みの利用区分だけを追加する。しかし所属なしでは有効な利用区分を選べない。

改善案：初回に「この地域で行うこと」を複数選択し、既存の認可ルールに沿って必要な所属を作る。設定後にも「利用する立場の追加」へ進めるようにする。地域管理の権限を任意の自己選択だけで付与する設計にはしない。

完了条件：新規利用者も、散布のみ・周辺農家のみ・散布＋地域管理の各構成で開始できる。既存利用者は同じアカウントに役割を追加できる。

補足：会話中の「地域作成後に散布者を選ぶ」という案内は、この経路では成立しなかった。既に散布者の所属がある場合と分けて案内する必要がある。

### 3. 新規の畑が、位置指定前に仮の場所へ描かれる【最優先・両画面幅で再現】

周辺農家として「自分の圃場を追加」を押した。位置・境界を一度も入力していないのに、地図用データには笠間周辺のPolygonが生成された。

`createBlankField` が乱数でx/yを割り当て、`normalizedFieldGeometry` がその値から緯度経度の図形を生成する。入力フォームにも位置を確定する工程がない。

改善案：位置未登録の畑は「位置を登録してください」と表示し、場所と境界を確定してから地図・距離計算へ載せる。既存の境界取込・筆選択を登録手順につなげる。

完了条件：新規追加しただけでは地図に図形が出ず、距離も断定されない。前回修正した既存デモの輪郭とは別に、新規登録側にも仮座標が残っていた。

### 4. 役割を切り替えて戻ると、元の作業対象に戻らない【高・両画面幅で再現】

散布者として `plan-kasama-demo` を選択 → 地域管理へ切替 → `plan-drone-2` を閲覧 → 散布者へ戻ると、選択は `plan-drone-2` のままだった。

改善案：地域と操作中の立場ごとに、最後に見ていた予定・画面・フィルターを保持する。管理画面から他の予定を見ても、散布者側の自分の作業を置き換えない。

完了条件：戻ったときに元の予定が選ばれ、どの地域・立場・予定を扱っているか画面に出る。

### 5. 散布者兼周辺農家が、同じ所有圃場を両方の立場で使えない【高・両画面幅で再現】

全３役を持ち、所有圃場が散布用の1件だけの利用者で周辺農家へ切り替えた。所有圃場は存在するのに、周辺農家側の対象は0件。保存されていない初期値の「自分の圃場」が代わりに表示された。

原因：`activeField`、`neighborRelevantNotices`、周辺農家ホームなどが `type !== "spray"` を条件にしている。

改善案：圃場の所有者・栽培状況と、その日の散布対象であることを分ける。同じ畑を散布予定にも近隣予定の確認にも利用できるようにする。

完了条件：所有する畑を二重登録しなくても、散布者としての予定作成と周辺農家としての近隣確認を行える。

### 6. 連絡文と相談文の書きかけが消える【高・両画面幅で再現】

- 散布者：連絡文を手直し → 同じ画面で相手の返答を選択すると、手直しした文が消える。
- 周辺農家：予定Bの相談文を書きかける → 予定Aの「確認しました」を押すと、Bの書きかけが消える。

これらの入力欄はフォーム単位の下書き保持の対象外。画面全体の再描画で置き換わった。

改善案：予定・宛先・連絡内容の版ごとに下書きを保持する。別の対象への操作では書きかけを消さず、内容の版が変わった場合は古い文面であることを案内する。

完了条件：他の返答の記録・別のお知らせへの確認・通常の画面更新後にも書きかけが残る。返信を必須にする変更はしない。

### 7. 管理者が参加者を招待・役割追加する入口がない【高・画面とコードで確認】

管理一覧・設定画面にあるのは「招待された地域へ参加」のコード入力欄。招待を発行する画面と参加者・役割の一覧は見つからない。DBには `create_workspace_invite` があるが、ブラウザーの招待発行導線へ接続されていない。

改善案：地域管理に「参加者」を設け、招待コード/QRの発行と利用できる立場の確認・追加を行えるようにする。既定の本人同意と認可ルールを維持する。

完了条件：管理者が招待を用意し、本人が同意して参加できる。既存参加者が兼務を追加する場合も、別アカウントや地域の作り直しを要求しない。

### 8. 新しい地域にも、サンプル予定と畑が入る【高・表示まで再現】

初回作成した地域を選択した直後、予定5件・畑7件が端末状態に存在した。`performDeviceStateContextSwitch` が空の状態へサンプルを補充している。

改善案：実利用の新規地域は空から始め、最初に畑を登録する案内を出す。体験用サンプルは独立した保存領域に置く。「クラウドへ移行」も何を共有するか明示する。

完了条件：実利用の新しい地域に架空の予定が初期表示されない。今回クラウドへサンプルを送信した事実はなく、共有先を誤認しやすい表示と移行導線を問題としている。

### 9. 初期設定が長く、登録すべき情報が遠い【中・寸法を確認】

390px幅・900px高の画面で、プロフィール本体の開始位置はページ先頭から約2,100～2,400px。設定ページ全体は約5,900～6,500px。散布予定フォームは表示中の名前付き入力要素が31個あり、プロフィールには立場に応じて23～31個あった。計測値は今回の仮想データでの値。

アカウント、地域作成、招待、同期、データ出力、退会の操作がプロフィールより先に並ぶ。設定できていない項目の必須・任意も分かりにくい。

改善案：初回は氏名・連絡方法・利用する立場・対象地域に絞る。機体等は既定値設定、共有管理・退会等は別の設定へ整理する。登録済みには「登録」ではなく「設定」と表示する。

完了条件：初回の画面で次の入力が見つかり、基本情報だけで作業を始められる。

### 10. 登録・ログイン・地域所属・同期の説明が混在する【中・画面で確認】

登録済みの仮想アカウントに対し、アカウント欄は「接続済み」、別の場所は「端末に保存」、PCのプロフィール説明には「本番認証ではなく、localStorage上のUI制御」と出る。本人情報の設定と実際のログイン状態を見分けにくい。周辺農家・地域管理では登録後もナビに「登録」が残る。

改善案：現在の地域・操作中の立場を常時表示し、ログイン状態とデータの保存先をそれぞれ短い言葉で示す。実装方式の説明は製品画面から外す。

完了条件：「誰として・どの地域で・どの立場で操作中か」「この入力は保存済みか」を画面で読み取れる。

## 兼務の設計案

| 管理するもの | 役割 |
| --- | --- |
| アカウント | 同じ人は1つのログイン。氏名・連絡先を共通管理 |
| 地域への所属 | 同じ人が地域ごとに複数の役割を持つ。認可はここで管理 |
| 操作中の立場 | いま表示する仕事を1つ選ぶ。プロフィールや既存の予定は書き換えない |
| 圃場 | 所有・栽培状況を保持。同じ畑を複数の仕事で使う |
| 作業の続き | 地域×立場ごとに選択中の予定・画面・下書きを保持 |

推奨順：1・2・3で誤更新と登録の行き止まりを解消 → 4・5・6で兼務と下書きを安定させる → 7・8で参加・実利用開始を整える → 9・10で画面を短く分かりやすくする。料金・通知方式・閲覧権限を変更する提案ではない。

## 維持したい点

有効な役割が既に付与されている場合の切り替えボタン、散布者の３入口、地域作成後の現在地カードは機能していた。今回観察したホーム・設定画面では横方向のはみ出しはなかった。周辺農家への返信が任意である旨も表示されている。
